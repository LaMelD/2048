# 2026-09-22 — T10 서명·출시

## 왜 하는가

코드·실기기 검증(T1~T9, T11~T13)이 끝났다. Play에 올릴 서명된 AAB를 만들고, 필수 정책 문서를 배포한다.
계획 `docs/superpowers/plans/2026-09-22-2048.md` T10.

## 사전 확인 (사용자 답변 대기)

1. 키스토어 생성 방식·비밀번호
2. Play 개발자 계정 종류 — 개인 신규면 12명×14일 비공개 테스트 선행
3. 개인정보처리방침 호스팅 위치

| 항목 | 답변 | 영향 |

| 방침 호스팅 | `lameld.github.io` 저장소 | Hugo 사이트(Actions 빌드). `static/2048/privacy.html` → `https://lameld.github.io/2048/privacy.html` |

## 결정

- `signing-fallback-to-debug`: `build.gradle`의 `buildTypes.release.signingConfig`를 삼항으로 —
  `GAME2048_UPLOAD_STORE_FILE` 프로퍼티가 있으면 release 키, 없으면 debug 키. 계획은 release 블록만
  두는 것이었으나, 프로퍼티 없는 환경에서 `storeFile`이 null이면 `assembleRelease`가 실패한다.
  폴백이 있으면 CI·다른 체크아웃에서도 빌드는 항상 되고, 서명만 debug가 된다.
- minify·shrink는 Expo 템플릿의 `findProperty('android.enableMinifyInReleaseBuilds')` 방식을 그대로 둔다.
  계획은 `true` 하드코딩이었으나 템플릿 관례를 따르는 편이 낫다.

## 실행

```
build.gradle  signingConfigs.release + buildTypes.release 삼항 폴백 (gradle 구성 에러 없음)
docs/privacy.html  작성 (42줄)
lameld.github.io   static/2048/privacy.html  PUT via GitHub API → Actions 배포 트리거
```
