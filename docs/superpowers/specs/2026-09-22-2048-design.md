# 2048 (React Native) 설계

작성일: 2026-09-22
상태: 승인됨

## 1. 목표

React Native로 2048 게임을 만들어 Google Play에 출시한다. 안드로이드 단독 출시이며,
완전 무료이고 수익화 요소가 없다.

## 2. 범위

포함:

- 4x4 격자, 스와이프 병합, 점수, 게임오버 판정, 새 게임
- 타일 이동·생성·병합 애니메이션
- 최고 점수 영구 저장
- 이어하기 (앱을 껐다 켜면 진행 중이던 판 복원)
- 되돌리기 1회
- Google Play 출시에 필요한 서명·버전·스토어 자산·정책 문서

제외:

- iOS 출시 (코드는 RN이라 추후 가능하나 이번 범위 밖)
- 광고, 인앱 결제, 계정, 서버, 리더보드
- 4x4 이외의 격자 크기, 테마 선택

## 3. 기술 선택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Expo (blank-typescript) | prebuild로 android/를 생성해 로컬 gradle 빌드. Expo 계정 불필요 |
| 애니메이션 | RN 내장 Animated + useNativeDriver | 타일 16개의 transform 이동에 충분. Reanimated는 이 게임에서 쓸 자리가 없음 |
| 제스처 | RN 내장 PanResponder | 드래그 종료 시 dx/dy 비교 한 줄이면 방향이 나옴 |
| 상태 관리 | useReducer 1개 | 전역 상태 라이브러리를 쓸 규모가 아님 |
| 영속화 | @react-native-async-storage/async-storage | 유일한 추가 의존성 |
| 테스트 | node --test (Node 24 내장 TS 실행) | 순수 로직만 검증하므로 테스트 프레임워크가 불필요 |

추가 런타임 의존성은 AsyncStorage 하나뿐이다.

## 4. 구조

```
2048/
├── app.json                 # 패키지명·버전·아이콘·세로고정
├── App.tsx                  # useReducer 상태, 화면 조립
├── src/
│   ├── game/board.ts        # 순수 로직 (RN 의존 0)
│   ├── game/board.test.ts   # node --test
│   ├── components/Board.tsx # 격자 + 스와이프 감지
│   ├── components/Tile.tsx  # 개별 타일 애니메이션
│   └── storage.ts           # AsyncStorage 래퍼
├── assets/                  # 아이콘·스플래시
├── docs/privacy.html        # 개인정보처리방침 (GitHub Pages 배포)
└── android/                 # prebuild 산출물 — .gitignore
```

`android/`는 커밋하지 않는다. Expo가 `app.json`만 보고 언제든 재생성하므로,
커밋하면 설정 출처가 두 군데로 갈라져 시간이 지나면 반드시 어긋난다.
네이티브 설정을 바꿔야 하면 `app.json` 또는 config plugin을 고친다.

## 5. 게임 로직 (src/game/board.ts)

### 자료 구조

타일을 격자 배열이 아니라 id를 가진 객체의 배열로 관리한다.

```ts
type Tile = {
  id: number;      // 생성 시 부여, 병합·이동에도 유지
  value: number;   // 2, 4, 8, ...
  row: number;     // 0..3
  col: number;     // 0..3
};

type GameState = {
  tiles: Tile[];
  score: number;
  nextId: number;  // id 발급기
};
```

id가 있어야 "이 타일이 어디서 어디로 이동했는지"를 화면이 알 수 있고,
그래야 이동 애니메이션이 가능하다. 격자 배열만으로는 이동 전후를 연결할 수 없다.

### 공개 함수

모두 순수 함수이며 입력 상태를 변경하지 않는다.

- `newGame(): GameState` — 빈 판에 무작위 타일 2개를 놓는다. 값은 90% 확률로 2, 10% 확률로 4.
- `move(state, dir): GameState` — 한 수를 둔다. `dir`은 `'up' | 'down' | 'left' | 'right'`.
- `isGameOver(state): boolean` — 빈 칸이 없고 인접한 같은 값도 없으면 참.

### move의 규칙

1. 이동 방향 기준으로 각 줄을 훑어 타일을 끝으로 민다.
2. 같은 값이 만나면 병합해 값을 2배로 하고, 그 값을 점수에 더한다.
3. 한 수에서 이미 병합된 타일은 다시 병합되지 않는다.
   예: `2 2 4 4`를 왼쪽으로 밀면 `8`이 아니라 `4 8`이다.
4. 타일이 하나도 움직이지 않았고 병합도 없었다면 **입력 상태를 그대로 반환한다.**
   새 타일을 놓지 않는다. 이로써 "막힌 방향으로 스와이프해도 판이 진행되지 않는다"는
   규칙이 별도 분기 없이 지켜진다.
5. 변화가 있었다면 빈 칸 중 하나를 무작위로 골라 새 타일을 놓는다.

병합된 타일의 id는 두 타일 중 이동 방향 앞쪽 타일의 id를 물려받는다.
사라지는 타일의 id는 버린다. 화면은 사라진 id를 언마운트한다.

### 승리 조건

2048 타일이 나와도 게임을 멈추지 않는다. 계속 진행할 수 있으며,
별도의 승리 화면을 두지 않는다. 게임은 `isGameOver`가 참일 때만 끝난다.

## 6. 화면

### Board.tsx

- 배경에 빈 칸 16개를 고정 격자로 깐다.
- 타일은 그 위에 `position: absolute`로 띄운다.
- `PanResponder`로 드래그를 받고, 손을 뗀 시점의 `dx`, `dy` 중 절대값이 큰 축을
  방향으로 삼는다. 이동량이 임계값(20dp) 미만이면 무시한다.

### Tile.tsx

- 타일마다 `Animated.ValueXY`를 하나 들고, `row`/`col`이 바뀌면
  `Animated.spring`으로 목표 좌표까지 움직인다. 지속시간은 약 100ms.
- 새로 생긴 타일과 병합 결과 타일은 scale 팝(0.8 → 1.0)을 준다.
- 모든 애니메이션은 transform만 다루므로 `useNativeDriver: true`를 쓴다.

### 헤더

현재 점수, 최고 점수, 새 게임 버튼, 되돌리기 버튼을 둔다.
되돌릴 상태가 없으면 되돌리기 버튼을 비활성화한다.

## 7. 영속화 (src/storage.ts)

AsyncStorage에 키 하나로 JSON 한 덩어리를 저장한다.

```ts
type Saved = { tiles: Tile[]; score: number; nextId: number; best: number };
```

- 매 수마다 저장한다.
- **저장 실패는 무시한다.** 저장이 안 된다고 게임이 멈출 이유가 없다.
- 앱 시작 시 읽는다. 값이 있으면 그 판을 복원하고, 없거나 파싱에 실패하면 새 게임을 시작한다.
- 최고 점수는 같은 덩어리 안에 둔다. 새 게임을 눌러도 최고 점수는 유지된다.

## 8. 되돌리기

직전 상태 1개만 변수에 보관하다가, 되돌리기를 누르면 교체한다.
히스토리 스택을 만들지 않는다. 되돌린 직후에는 되돌릴 대상이 없으므로 버튼이 비활성화된다.

## 9. 출시 준비

| 항목 | 값 / 방식 |
| --- | --- |
| 패키지명 | `io.github.lameld.game2048` — Play 업로드 후 영구 고정 |
| 산출물 | AAB (`./gradlew bundleRelease`). 기기 직접 설치 테스트용으로만 APK |
| 서명 | 업로드 키스토어를 로컬 생성하고 Play App Signing에 위임 |
| 비밀 관리 | 키스토어 파일과 비밀번호는 커밋하지 않는다. `.gitignore`에 포함하고 `gradle.properties`는 로컬에만 둔다 |
| 버전 | `version: "1.0.0"`, `versionCode: 1`. 제출마다 versionCode를 정수로 올린다 |
| 화면 방향 | 세로 고정 |
| 시스템 UI | edge-to-edge 대응. Android 15부터 강제되므로 안전 영역 패딩을 적용한다 |
| 아이콘 | 적응형 아이콘(전경·배경 분리) + 스토어용 512x512 |
| 타겟 SDK | Expo SDK 기본값을 따르되, 제출 전 Play Console 경고로 최신 요구 수준을 확인한다 |

### 정책 대응

데이터를 일절 수집하지 않는다. 점수와 진행 상황은 전부 기기 내부에만 저장되며
네트워크로 나가지 않는다.

- 데이터 안전 양식: "수집하는 데이터 없음", "공유하는 데이터 없음"
- 개인정보처리방침: 위 내용을 담은 정적 HTML 1장을 GitHub Pages로 배포하고
  Play Console에 URL을 등록한다. 방침 URL은 Play Console 필수 입력 항목이다.
- 콘텐츠 등급: 설문에 응답해 전체이용가를 받는다.

### 스토어 자산

- 폰 스크린샷 2장 이상 (최대 8장)
- 피처 그래픽 1024x500
- 짧은 설명 80자 이내, 긴 설명 4000자 이내

### 계정 관련 사전 확인

Play 개발자 계정을 **개인**으로 신규 개설하는 경우, 프로덕션 출시 전에
테스터 12명이 14일간 비공개 테스트를 진행해야 한다. 조직 계정은 이 요건이 없다.
코드 진행과 무관하게 달력상 2주가 걸리므로 계정 종류를 먼저 확인한다.

## 10. 검증

`src/game/board.ts`만 테스트한다. `node --test`로 실행하므로 테스트 의존성이 없다.

검증 항목:

1. 병합 규칙: `2 2 4 4`를 왼쪽으로 밀면 `4 8`이 된다 (한 수에 이중 병합 금지)
2. 점수 누적: 병합으로 생긴 값의 합이 점수에 더해진다
3. 이동 불가: 막힌 방향으로 밀면 상태가 그대로이고 새 타일이 생기지 않는다
4. 새 타일: 이동이 있었으면 타일이 정확히 하나 늘어난다
5. 게임오버: 빈 칸이 없고 인접한 같은 값이 없을 때만 참
6. id 보존: 이동한 타일의 id가 유지된다 (애니메이션의 전제)

컴포넌트 테스트와 E2E 테스트는 만들지 않는다.
화면 동작은 실제 기기에 설치해 직접 확인한다.
