# 2026-09-22 — Play Console 제출 (Claude in Chrome)

## 왜 하는가

사용자가 "대신 업로드해줘"로 Play Console 조작을 위임. AAB 드래그와 그래픽 드래그만 사용자가 하고
나머지 폼·설문·선언은 브라우저 자동화로 처리했다.

## 발견 (착수 시점)

- 개발자 계정 `LaMelD`가 이미 있었다 (사용자가 "신규 개설"이라 했지만 존재). 결제 단계 없음.
- 앱 `2048`(패키지 `io.github.lameld.game2048`)과 비공개 테스트 버전 `2048 No ad`, 출시 노트까지
  사용자가 미리 만들어 둔 상태.
- **vc1.aab 업로드가 "버전 코드 1은 이미 사용됨"으로 실패해 있었다.** Play는 한 번 올라간 versionCode를
  삭제해도 재사용 불가. → versionCode 2로 재빌드 (`65c3b04`).

## 함정 (브라우저 자동화)

- **파일 업로드 불가.** `file_upload` 툴은 10MB 제한이고, Play Console은 `<input type=file>`을 DOM에
  두지 않고 네이티브 선택기를 연다. AAB·그래픽은 사용자가 드래그해야 한다. 단, 라이브러리에 올라간
  그래픽을 슬롯에 배치하는 건 DOM 조작이라 가능 — 항목에 **hover 후** "→" 버튼이 나타나고, 상세 보기의
  "추가"로 슬롯에 들어간다. hover 없이 "→" 좌표를 바로 클릭하면 안 먹는다.
- **콘텐츠 등급 설문은 "저장"이 "다음"의 선행 조건.** 모든 항목을 답해도 저장 전엔 다음이 비활성.
- **`find`가 실패하면 같은 batch의 앞선 스크린샷까지 결과에서 생략된다.** 상태 확인용 스크린샷은
  find와 분리하거나, `get_page_text`/`read_page`로 대체한다.
- `find`는 라디오 선택 상태를 정확히 못 읽는다 (선택된 것도 "unselected"로 보고). 상태는 스크린샷으로.
- ref 클릭은 요소가 화면 밖이면 안 먹는다. `scroll_to` 후 클릭.
- `type`으로 한글 입력 시 IME 조합 오타가 난다("합쳐"→"합쳤"). 긴 한글은 `form_input`으로 값을 통째로.
  단, 유니코드 이스케이프로 쓰면 코드포인트 실수가 나므로 한글을 직접 쓴다.
- 대시보드 체크리스트의 ref 번호는 페이지 재로드 후 대체로 유지되지만, 로드 직후엔 없을 수 있다 (wait 6초).
- "저장"은 임시 저장일 뿐 제출이 아니다. 제출은 **게시 개요 → 검토를 위해 변경사항 N개 제출 → 확인**.
- 제출 전 "빠른 검사"(최대 14분)가 돌지만 제출 버튼을 막지는 않는다. "발견된 문제"만 해결하면 된다.
