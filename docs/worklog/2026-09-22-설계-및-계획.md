# 2026-09-22 — 설계 확정과 계획 수립

## 왜 하는가

빈 저장소에서 2048 게임을 React Native로 만들어 Google Play에 출시한다.
이 문서는 착수 시점의 실측값과 결정을 남긴다. 코드 작업은 Codex CLI에 위임한다.

## 실측된 사실

개발 환경 (직접 실행해 확인):

```
Node        v24.15.0
npm         11.12.1
JDK         openjdk 21.0.12.1 (Homebrew)
Android SDK ~/Library/Android/sdk (build-tools, ndk, platforms 설치됨)
adb         ~/Library/Android/sdk/platform-tools/adb
연결 기기    없음 (adb devices 결과 비어 있음)
```

패키지 최신 버전 (`npm view`로 조회):

```
expo                                          57.0.24
create-expo-app                               5.0.0
expo-template-blank-typescript                57.0.26
@react-native-async-storage/async-storage     3.1.1
```

Node 24가 TypeScript를 무설정으로 실행하는지 직접 검증했다. 통과했다.

```
$ node --test t.test.ts
✔ adds (0.53ms)
ℹ pass 1  fail 0
```

조건: TypeScript 파일을 import할 때 확장자 `.ts`를 명시해야 한다.
Metro 번들러는 반대로 확장자를 붙이지 않는 것이 관례이므로, 테스트가 import하는
모듈은 RN 의존성을 가지면 안 된다. 이 제약이 `storage-parse.ts` 분리의 근거다.

## 결정 사항

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| `expo-local-build` | Expo + `expo prebuild` + 로컬 gradle | Android SDK가 이미 있음. Expo 계정·클라우드 빌드 대기 불필요 |
| `deps-asyncstorage-only` | 추가 런타임 의존성은 AsyncStorage 하나 | 애니메이션은 RN 내장 `Animated`, 제스처는 내장 `PanResponder`로 충분 |
| `android-dir-committed` | `android/`를 커밋한다 | 릴리즈 서명 설정이 `android/app/build.gradle`에 살아야 하는데, gitignore하면 `expo prebuild` 재실행 때 사라진다 |
| `package-id-fixed` | `io.github.lameld.game2048` | Play 업로드 후 영구 변경 불가 |
| `no-monetization` | 광고·IAP 없음, 네트워크 미사용 | Play 데이터 안전 신고가 "수집 데이터 없음" 한 줄로 끝난다 |
| `codex-handoff` | 구현은 Codex CLI에 위임 | 코드 생성 토큰을 Claude 밖으로 돌린다 |

## 기각된 것

| 기각 | 이유 |
| --- | --- |
| react-native-reanimated + gesture-handler | 2048은 "스와이프를 놓으면 이동"이라 드래그 추적 연출을 쓸 자리가 없다. 의존성 2개와 babel 설정이 값을 못 한다 |
| EAS Build (클라우드) | 로컬 Android SDK가 이미 있다. 계정 가입과 무료 티어 대기가 순손실 |
| iOS 동시 출시 | 이번 범위 밖. Apple 개발자 계정 연 99달러와 심사 대응이 붙는다 |
| 애니메이션 없는 최소 구현 | 2048의 손맛이 사라진다 |
| `gen-history-index.py` 도입 (work-history 4단계) | 이 프로젝트는 이슈 10건 규모다. 스킬 자체가 "이슈 수백 건 규모부터"로 손익분기를 명시한다. frontmatter는 비용이 0이라 지금부터 붙여두었으므로, 필요해지면 스크립트만 복사하면 켜진다 |

## 계획 자체 검토에서 잡은 결함 4건

계획을 쓴 뒤 스펙과 대조하며 찾아 고쳤다. 고치지 않았다면 Codex가 그대로 구현했을 것들이다.

1. **import 확장자 규칙 충돌** — `node --test`는 `.ts` 명시를 요구하고 Metro는 붙이지 않는 것이 관례다. 계획이 전자만 전역 규칙으로 서술하고 있었다.
2. **`storage.ts`가 테스트 불가** — AsyncStorage를 import하는 파일을 `node --test`가 로드하면 터진다. 파싱 로직을 `storage-parse.ts`로 분리했다.
3. **`setState` updater 안에서 다른 `setState` 호출** — updater는 순수해야 하고 StrictMode에서 두 번 호출될 수 있어, 되돌리기 상태와 최고 점수가 어긋난다. updater 밖으로 뺐다.
4. **앱 아이콘 교체 단계 누락** — create-expo-app이 넣는 Expo 로고를 그대로 출시할 수 없다. Task 9에 교체 단계를 넣었다.

## 곁가지 — 텔레그램 알림 중복 전송 원인 규명

사용자가 훅이 2번 도는 것 같다고 하여 조사했다. 상시 버그가 아니라 조건부였다.

`telegram-alarm` 0.1.0과 0.1.2의 마커 파일 경로가 다르다.

```
0.1.0: $TMPDIR/telegram-alarm/<세션ID>
0.1.2: $TMPDIR/telegram-alarm-<uid>/<세션ID>
```

스크립트는 SessionStart 때 자기 절대경로를 컨텍스트에 주입한다. 세션 도중
`/reload-plugins`를 하면 Stop 훅만 새 버전으로 갱신되고, 컨텍스트에 이미 들어간
지시문은 옛 경로를 들고 있다. 그래서 옛 경로로 마커를 만들고 새 훅이 못 찾아 차단하고
재전송한다. 결과가 같은 내용 2통이다.

트랜스크립트 실측 (github-control-panel 세션 6d43a3a9):

```
line598  /plugin
line602  /reload-plugins
line642  0.1.0 스크립트로 send  → 옛 경로에 마커 생성
line647  0.1.2 훅이 차단        → 새 경로에 마커 없음
line650  0.1.2 스크립트로 재전송 → 텔레그램 2통째
```

조치: 미등록 캐시 잔재인 `0.1.0` 디렉토리를 삭제했다. `installed_plugins.json`에는
0.1.2만 등록되어 있었으므로 안전하다.

미조치: `~/.claude/settings.json`에 GitHub PAT와 텔레그램 봇 토큰이 평문으로 있다.
사용자에게 알렸고 조치는 사용자 판단에 맡겼다.
